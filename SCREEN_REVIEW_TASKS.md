# Screen review and annotations

Scope: the clickable demo editor. This work does not change the review workflow for other artifact types.

## Tasks

- [x] **Show usable edits as the current snapshot.** When an edit produces a usable demo, save it and show it in the editor without an accept/reject step. Use the existing snapshots to reopen earlier results; do not add a separate versioning system. Keep incomplete results, unsafe markup, broken core interactions, and changes outside the requested scope from replacing the current snapshot.
- [x] **Make uncertain checks warnings, not failed edits.** Report layout and other findings that do not make the demo unusable as warnings. Name the affected screen and describe what the check found. Do not show **Failed** or prompt users to retry because of a warning. If an edit produces no usable result, keep the current snapshot and report the actual failure.
- [ ] **Remove the separate draft workflow for demos.** Remove the **Draft**, **Saved version**, and **Review draft** switches and the separate play-draft action. Use the same editor, **View**, and export actions for the current usable snapshot. Preserve existing retained drafts during the transition; do not silently delete them or publish them without checking they are usable.
- [ ] **Mark screens changed by the latest edit.** Show **New** on thumbnails of screens added by the edit and **Edited** on thumbnails of existing screens it changed. Leave untouched screens unmarked. Keep the badges when users move between screens or reload the editor. Update them after the next successful edit; a warning or failed edit must not clear them. The badges report changes, not approval.
- [ ] **Let users mark and comment on any screen.** Open the selected screen in an annotation mode. Let users draw a box around an element or region, add a comment, and edit or remove the annotation before submitting. Allow multiple boxes on one or more screens. Keep boxes attached to the same screen coordinates as the preview scales. Drawing a box must not trigger the prototype controls beneath it.
- [ ] **Send annotations as one scoped edit.** Start work only when the user submits. Send the model the exact snapshot and screen content the user marked, the box coordinates in screen space, a rendered image showing the marked region, and the associated comment. Change only annotated screens and only what the comments ask to fix; preserve unrelated content, screen order, links, and shared settings. If a marked screen has changed since it was annotated, ask the user to review the mark rather than silently applying it to the new content. Keep comments and boxes if submission fails.
- [ ] **Verify the full workflow.** Test that a false overlap warning does not force a retry; unusable or unsafe results do not replace the current snapshot; **New** and **Edited** are applied correctly; and annotations stay aligned after zoom or resize. Submit comments on two screens and verify the model receives the right regions and that all other screens remain unchanged. Check that **View**, export, and reopening an earlier snapshot still work. Use candidate 8’s Project Access dialogs as a regression case without changing live project data during tests.
